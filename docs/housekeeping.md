# Housekeeping rules

## Keep information in one place

Facts and claim evidence live in the profile. Preferences and design choices
live in profile/preferences.md. Reusable CV/letter text lives in personal/master.
Role-specific requirements and tailoring live under applications. Instruction
files contain durable rules, not dates, personal facts or today's tasks.

Use filenames consistently. Do not create final-final or competing masters.
A source is canonical; a PDF or DOCX is an export. Record which source/version
produced each approved export. Keep the distributed fictional examples intact.

## Changes and versions

Before editing, inspect the current source and any existing changes. Make small,
reviewable edits. For a previously approved document, retain a source/export
snapshot under an explicitly named approved version before replacing it.
Draft changes need no repeated permission. Approval, publishing and submission
are separate events; preserve the user's authorization scope.

A corrected fact must be reconciled across active sources. Historical submitted
copies remain unchanged; record the correction separately. Do not erase useful
history or delete material without authorization. No automatic cleanup job runs.

## Verification

Content-only edits require checks on affected documents, not every unrelated
application. Shared Python, fonts or CSS changes require the example regression
build and visual review of affected layouts. Reuse still-valid evidence; mark
stale review results when source or renderer changes. Do not mark a check passed
without running it or a draft approved without explicit user confirmation.

## End of a working session

Update the private status with the current stage, unresolved questions and one
next action. Record actual validation and approval evidence in the document's
review file. Keep user-facing updates short and report the result or blocker.

Before an authorized push, inspect all staged paths and exports. Ignored files
can still be added with force, and a private remote still shares data with its
collaborators. Never add personal content to templates, example fixtures or
instruction files. Changing the privacy policy requires the user's direction.
